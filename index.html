Allowances, not blank checks

A controller-signed policy answers one question for every payment: can this agent spend this amount, with this merchant, for this resource, right now? Off-policy payments are blocked before the signer is ever invoked.

x402-native

Wrap the fetch your agent already uses. HTTP 402 challenges are parsed, the allowance is evaluated, and only approved payments reach the EIP-3009 USDC signer — which carries its own hard cap and refuses unknown tokens.

Verifiable receipts

Allowed and denied decisions persist with their reasons, and receipts can be anchored to the no-custody onchain registry. Replays, over-cap amounts, and unknown merchants revert — provable by anyone, gas-free.

Integrate in ~10 lines

import { createAllowFetch } from "allow-protocol/allow-fetch";
import { createX402Payer } from "allow-protocol/x402-payer";
import { createJsonlReceiptStore } from "allow-protocol/receipts";

const fetch = createAllowFetch({
  policy: { perTxCapUsd: 1.5, dailyCapUsd: 25, allowedMerchants: ["mcp_search"] },
  resolveMerchant: (req) => merchantFor(req.payTo),
  pay: createX402Payer({ account, perTxCapUnits: 1_500_000n }),
  receiptStore: createJsonlReceiptStore("agent-receipts.jsonl")
});

Experimental demo. Allow Protocol is no-custody infrastructure for agent payment policy checks. It is an unaudited prototype: the registry records policies and receipts only, never funds.
